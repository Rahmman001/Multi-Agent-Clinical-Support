# PRD: Multi-Agent Clinical Decision Support System

## 1. Introduction & Overview

Modern Electronic Health Records (EHRs) are dense, fragmented, and unstructured. A single patient file typically contains clinical encounter notes, multi-year laboratory tables, medication lists, and vital sign logs. Pushing this entire unstructured payload into a single, monolithic LLM prompt leads to hallucinated values, missed subtle drug-drug interactions, and cognitive fatigue for attending clinicians.

**Multi-Agent Clinical Support** treats AI like a team of specialized hospital assistants rather than one overloaded chatbot. Instead of a single LLM trying to parse every domain simultaneously, the system dispatches modular, deterministic, domain-specific AI agents that run parallel extractions, cross-reference clinical rules with validated schemas, and synthesize a single, triage-scored clinical summary card for the doctor.

---

## 2. Goals

- **Zero Monolithic Hallucinations**: Enforce schema validation (Pydantic) for each domain agent so outputs are structured, typed, and verifiable.
- **Specialized Multi-Agent Routing**: Segment extraction into three parallel domain agents: Lab Agent, Pharma/Medication Agent, and History Agent.
- **Deterministic Risk Triaging**: Coordinate agent outputs via a Lead Triage Agent that assigns a definitive triage score (**HIGH**, **MEDIUM**, **LOW**) with clinical rationale.
- **Actionable Clinician UI**: Deliver an intuitive Doctor Triage Dashboard with color-coded risk alerts and collapsible evidence trails.
- **Reproducible Synthetic Benchmark**: Ingest and process FHIR/JSON records generated by [Synthea](https://synthetichealth.github.io/synthea/) without requiring real patient PHI.

## 4. User Stories

### US-001: Synthetic Patient Data Ingestion & Parser (Stdlib First)
**Description:** As a developer, I want a lightweight parser that loads Synthea-generated patient JSON records without heavy third-party FHIR dependencies so that domain agents receive clean clinical dictionaries.

**Acceptance Criteria:**
- [ ] Ingestion script uses Python stdlib `json` + simple dict navigation (zero bloated FHIR packages).
- [ ] Extracts key resources into structured lists: `labs`, `medications`, `conditions`, and `patient_info`.
- [ ] Rejects malformed records with clear validation errors.
- [ ] Unit tests verify extraction of normal and abnormal patient records.

---

### US-002: Laboratory Findings Domain Agent
**Description:** As a clinician, I want a specialized Lab Agent that detects abnormal trends and acute value jumps so that organ distress (e.g., acute kidney injury) is immediately surfaced.

**Acceptance Criteria:**
- [ ] Lab Agent extracts numerical lab test results (e.g., Creatinine, eGFR, Potassium, Hemoglobin, WBC).
- [ ] Evaluates values against clinical reference intervals and identifies delta jumps (e.g., $>40\%$ jump in 48 hours).
- [ ] Outputs strict Pydantic model: list of flagged anomalies with severity, delta, reference range, and clinical note.
- [ ] Project quality checks pass (unit tests covering normal and abnormal lab series).

---

### US-003: Pharmacology & Drug-Drug Interaction Agent (Local Rule Dict + LLM)
**Description:** As a clinician, I want a Pharma Agent that cross-references active prescriptions against known lethal contraindications using an instant local rules lookup table with local LLM fallback.

**Acceptance Criteria:**
- [ ] In-memory Python rule dictionary checks high-risk combos in $O(1)$ (Triple Whammy: ACEi + Diuretic + NSAID; Anticoagulant + NSAID; Spironolactone + ACEi).
- [ ] Local Ollama model acts as fallback for nuanced/unstructured medication instructions.
- [ ] Outputs structured Pydantic model: interacting drug pair, severity (Major, Moderate, Minor), mechanism, and recommendation.
- [ ] Zero external network calls or third-party paid API dependencies.

---

### US-004: Medical History & Chronic Condition Agent
**Description:** As a clinician, I want a Medical History Agent that extracts past diagnoses, chronic diseases, and recurring symptoms so that acute findings are interpreted in patient context.

**Acceptance Criteria:**
- [ ] History Agent scans encounter notes and diagnostic problem lists.
- [ ] Extracts confirmed chronic conditions (e.g., Type 2 Diabetes, CKD, Hypertension, COPD) with onset date.
- [ ] Outputs structured Pydantic model of active and historical conditions.
- [ ] Project quality checks pass.

---

### US-005: Lead Triage Coordinator Agent
**Description:** As a clinician, I want a Lead Triage Agent that synthesizes the reports of all domain agents, deduplicates findings, and computes an overall patient risk score.

**Acceptance Criteria:**
- [ ] Orchestrator (LangGraph state graph) passes patient data concurrently to Lab, Pharma, and History agents.
- [ ] Lead Triage Agent aggregates all three outputs into a unified clinical state.
- [ ] Assigns an overall triage risk level: `HIGH` (immediate danger / critical lab / major interaction), `MEDIUM` (abnormal trends / chronic risk), or `LOW` (routine / stable).
- [ ] Formulates a concise 3-paragraph executive clinical summary.
- [ ] Project quality checks pass.

---

### US-006: Doctor Triage Dashboard UI (Pure Streamlit)
**Description:** As an attending physician, I want an interactive, color-coded triage screen built purely in Streamlit so I can select a patient, view their triage risk badge, and inspect the itemized evidence card without frontend build complexity.

**Acceptance Criteria:**
- [ ] `st.sidebar.radio` patient triage queue with native arrow-key navigation.
- [ ] Prominent risk alert banner (Red = High, Yellow = Medium, Green = Low).
- [ ] Three modular panels: Lab Alerts, Drug Contraindications, Chronic Context.
- [ ] Collapsible `st.expander` displaying the verified Pydantic JSON state.
- [ ] Runs with a single command: `streamlit run app.py`.

## 5. Functional Requirements

- **FR-1**: The system must ingest Synthea patient JSON files from a designated `data/patients/` directory.
- **FR-2**: All LLM calls must output strict JSON conforming to validated Pydantic models (no unparsed markdown or free-form strings).
- **FR-3**: The agent orchestrator must execute the Lab, Medication, and History agents in parallel using LangGraph StateGraph nodes.
- **FR-4**: If an agent fails or produces invalid JSON, the orchestrator must invoke a retry schema repair loop before bubbling up an error.
- **FR-5**: The Lead Triage Agent must evaluate composite risks (e.g., high creatinine + NSAID prescription + history of diabetes = HIGH risk composite alert).
- **FR-6**: The UI must display patients ranked by risk severity (High risk patients sorted to the top).

---

## 6. Non-Goals (Out of Scope)

- **No Real PHI / HIPAA data**: System is built exclusively for synthetic data (Synthea).
- **No Direct EHR Write-Back**: Read-only decision support; does not commit orders or sign prescriptions into clinical EHR systems.
- **No Autonomous Prescriptions**: The system acts strictly as an AI assistant / second pair of eyes; human clinicians make all diagnostic and treatment decisions.

## 7. Technical Considerations & Stack (100% Free & Open-Source)

> **Zero Credit Card Constraint**: All tools, libraries, models, and runtimes must be 100% free and open-source. No paid APIs or credit card-gated services.

| Layer | Technology | Rationale & Cost |
| :--- | :--- | :--- |
| **Data Ingestion** | Synthea (JSON/FHIR) | Open-source realistic synthetic patient records ($0, zero PHI risk). |
| **LLM Inference** | **Ollama** (`llama3.2:3b` / `qwen2.5:7b`) | **100% Local & Free**. Runs on Apple Silicon / CPU. $0 cost, zero API keys, no credit card required. |
| **Agent Orchestration** | LangGraph (Python) | Open-source state graph framework for cyclic & parallel multi-agent flows. |
| **Data Validation** | Pydantic v2 | Open-source strict type and JSON schema validation. |
| **User Interface** | Streamlit (Python) | Pure Python, open-source reactive web dashboard running on localhost. |

---

## 8. Success Metrics

- **Zero Hallucinated Keys**: 100% of domain outputs strictly parse into Pydantic models.
- **Critical Interaction Recall**: 100% detection rate on known synthetic test cases with lethal/severe drug interactions.
- **Turnaround Time**: Full multi-agent evaluation completing in under 12 seconds on local Ollama inference.
- **Doctor Cognitive Load**: Key clinical risks summarized in $<150$ words per patient card.

---

## 9. Design Decisions & Zero-Cost Architecture

1. **Inference Engine**: Standardized on **Ollama** running locally on macOS. Alternative zero-cost fallback: Google AI Studio Gemini API free tier (which requires no credit card).
2. **Dashboard UI**: Standardized on **Streamlit** to eliminate frontend JavaScript build complexity, keeping the entire codebase in unified, clean Python.
